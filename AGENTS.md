## Поддерживаемая реализация

- Один Next.js+TypeScript проект; целевой предпочтительный стек Supabase Auth/Postgres/Storage,
  Tailwind/shadcn, Leaflet/OSM, Vercel. Интеграция выполняется после принятия ADR.
- Сохранить работающий прототип/пользовательские изменения. Новые общие UI/сервисы переиспользовать,
  не переписывать всю UI-систему или бизнес-логику без конкретной причины и проверки регрессии.
- Никаких микросервисов, универсальных repository-абстракций, очередей/Redis/realtime без доказанной нужды.
- SQL migrations + RLS — целевой единый источник схемы. Не вести независимые Drizzle и Supabase схемы.
- Feature service владеет правилами; Route Handler/Action тонкий. Server Components не вызывают
  собственный HTTP API. Многошаговые записи — небольшая атомарная RPC/транзакция с проверкой прав.
- Новая библиотека требует причины в DECISIONS/task log и проверки совместимости. Не добавлять
  зависимости «на будущее», не менять major versions ради устранения предупреждений без анализа.
- Использовать bundled Next.js guides для установленной версии; актуальные внешние API сверять
  с первичной официальной документацией. Не переносить случайный tutorial вместо местных правил.
- Обычные операции пользователя — scoped JWT client + RLS. Privileged client server-only,
  только для обоснованного bootstrap/Auth deletion/обслуживания, не для всего backend.

## Медицинские и персональные данные

- Только synthetic данные до согласования Q02 (размещение, согласия, retention, доступ).
  Не копировать настоящие анкеты/меддокументы в seed, git, тесты, логи или внешние сервисы.
- Не давать диагнозов, лечения, обещаний реабилитации и обязательных покупок. Чек-лист справочный,
  официальные URL+дата проверки обязательны для прав/льгот/организационных шагов.
- Auth, текущая role/status, ownership, consent и RLS проверяются каждым private запросом.
  Parent A не читает B; provider/staff не получает общий доступ к children. Скрытый UI не защита.
- Не доверять owner_id/role/verification_status из клиентского payload и JWT user_metadata.
  RLS защищает строки, а чувствительные/privileged колонки требуют grants/разделения DTO/RPC.
- Секреты не в NEXT_PUBLIC, browser, git или ответах/документах. Не выводить значения `.env.local`.
- Private ответы no-store, private страницы noindex. В аналитике/логах нет diagnosis, child_id,
  body анкеты, tokens, cookies, signed download URLs. Путь логировать шаблоном, не реальным private UUID.
- Детские документы — только флаги наличия справок, без настоящих uploads. Учебный fixture-разбор
  не является AI/PDF-интеграцией и не обязателен для нового full scope.
- Дипломы поставщиков private даже после verified. PDF/JPG/PNG≤10MiB: прямой Storage upload,
  init/finalize server validation; нельзя гонять10MiB через Vercel body4,5MB.
- Demo seed явно «Демо», без fake SMS/подтверждённых дипломов/настоящих отзывов.
  Unknown цена/язык/возраст/доступность не превращаются в подтверждённое условие.
- Клик контакта не запись/визит; self-confirmed отзыв не технически подтверждённый клиент.

## Проверки и завершение задачи

- Маленькими проверяемыми шагами. Для domain/DB изменений — meaningful unit/integration;
  SQL/FK/RLS проверять на реальной изолированной тестовой БД, включая прямой Data API.
- E2E основного пути и negative cases по AT-01…20; ru/kk, mobile360/390/768/1280,
  keyboard, labels, контраст и loading/empty/error/success.
- После кода: lint, typecheck, соответствующие тесты; перед завершением этапа — production build
  и фактический сквозной сценарий. Не заявлять новые результаты на основе старого отчёта.
- Для изменений только Markdown достаточно проверить ссылки, полноту/согласованность и diff;
  не устанавливать toolchain и не запускать ненужный build из-за документации.
- Не удалять/сбрасывать production БД или Storage. Действия запуска/публикации/платные ресурсы
  выполнять в разрешённом объёме. Подготовить reviewable результат до запроса финального согласования.
- Итог краткий: что изменено, проверено, что не готово, следующий разрешаемый этап. Не продолжать
  после остановки, установленной пользователем.
