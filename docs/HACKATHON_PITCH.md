# Mama Pro: концепция, демонстрация и проверка

## Актуальный демо-путь U1

Проблема-гипотеза: родителю трудно сопоставлять разрозненные условия и готовить первое
обращение, одновременно организуя заботу о ребёнке и о себе. Подтверждена командой потребность
в поддержке мамы; результаты самостоятельного родительского UX-теста пока не получены.

Демонстрация: пять коротких вопросов → варианты по возрасту/городу/языку → сведения о доверии
→ черновик обращения с выбранным возрастом/языком → один план действий. Дополнительный пример:
ПМПК → цитата → отклонить/исправить/подтвердить → потребность для поиска и цель с источником.
Показать RU и KK. При Астана/5/kk/речь честно нет совпадений; расширение только кнопкой родителя.

«Первый шаг вместе»: меньше повторного рассказа, понятные условия и необязательная поддержка
самому родителю. Состояние в памяти, все специалисты/контакты вымышлены. Проверка дипломов,
отправка, обработка реальных PDF и живой AI не заявляются. План пилота/бюджет остаётся гипотезой
из PRODUCT_REVIEW_2026-11-14.md. Тексты ниже — исторический H1, не актуальный список экранов.


> Перед использованием на защите свериться с [аудитом 14.11.2026](PRODUCT_REVIEW_2026-11-14.md).
> Этот питч описывает предыдущую версию: новые экраны R1/T2 не полностью переведены на KK,
> в карточках появились явно учебные отзывы/бейджи. Предложенный новый фокус — «Первый шаг вместе».
> Результаты родительского тестирования и реальная верификация по-прежнему не подтверждены.

Материал для подготовки защиты по §6 положения; это текстовая основа, не созданный PPTX и не
доказательство пользовательского теста. Все неподтверждённые показатели ниже — будущие измерения.

## Кому и зачем

**Проблема (гипотеза):** у родителя мало времени и сил сравнивать разрозненные предложения помощи.
Одновременно собственные потребности мамы оказываются без поддержки. Команда сообщила, что
родитель подтвердил нехватку поддержки/активностей для мамы, включая период беременности.
Точный опыт поиска, формулировки и поведение в интерфейсе ещё нужно проверить вместе с родителем.

**Пользователь:** родитель, который ищет помощь ребёнку и хочет сохранить небольшой следующий шаг
для себя. Нельзя считать, что у всех семей одинаковый диагноз, график или семейная ситуация.

**Концепция:** два равноправных входа: «Помощь ребёнку» и «Поддержка для меня».
Один простой план объединяет выбор помощи и время для мамы. Анкета с диагнозом не нужна для
демо-поиска; не добавляем ей ещё одну обязательную задачу и не даём медицинских назначений.

## Решение и доверие

Путь ребёнка: потребность → город/возраст/категория/язык → результаты → сравнение до3вариантов
по одинаковым полям → профиль → выбранный вариант в плане → подготовка первого обращения.
В demo контакт вымышленный: копирование текста работает, отправки нет. В пилоте после проверки
контактов появятся реальные phone/messenger/site действия без собственного бронирования.

Путь мамы: этап жизни (беременность/после рождения/воспитание) → доступное время → немедицинская
идея досуга → добавить в план → отметить выполнение. Это учебные идеи, не реальные события,
курсы, тренировки или медицинские программы. Ссылка поддержки взрослому ведёт к учебному психологу.

Matching детерминированный: только явно выбранные условия. Неизвестный язык не совпадает с
обязательным, несовместимый возраст исключается; unknown-age включается только явным флагом.
Позиция в выдаче не рейтинг лечения. Profile показывает услуги/условия/адрес/цену/языки/источник.
Рейтинг/стаж не выдуманы, demo не имеет badge verified. Production верификация — ручная проверка
закрытых документов модератором, отдельно от публикации карточки.

## Реализуемость и наполнение

Сейчас один Next.js-проект, существующая логика поиска/плана, typed ru/kk словари, fixtures и
React Context отдельной вкладки. Нет новой инфраструктуры для красивого демо. После refresh
учебное состояние сбрасывается, реальные детские данные не собираются, auth/Storage не имитируются.

Пилот: тот же Next.js + Supabase Auth/Postgres/RLS/Storage, один API в приложении. Редакторский
CSV-import и кабинет поставщика поддерживают базу; модератор проверяет контакты/документы,
каждое обновление имеет источник/дату. Свободные места устаревают при чтении по TTL, а не
остаются «открытыми» навсегда. Начать с одного подтверждённого города и небольшого проверенного набора.
Расширение: новые города/районы/услуги через справочники и повторяемый процесс редакции.
Не обещаем автоматическую актуальность всей страны и не делаем медицинский AI.

**Проектное распределение 300000₸ на ограниченный пилот**, не рыночная смета/согласованный бюджет:

| Направление | Резерв, ₸ | Что проверяем до обязательств |
|---|---:|---|
| Основной backend/авторизация/RLS/сохранение | 180000 | Оценка исполнителя на ограниченный сценарий, обязательные security tests |
| Начальная база/источники/редактура ru/kk | 40000 | Ответственный редактор, согласия и проверка контактов |
| QA/mobile/accessibility/user tests | 30000 | Реальное время проверки с родителем и исправления |
| Hosting/эксплуатационные подключения | 20000 | Фактические тарифы, регион/правовые условия, не расходовать автоматически |
| Резерв | 30000 | Непредвиденные работы |
| Всего | 300000 | Полное M01–M18 не обещается в этот бюджет без отдельной оценки |

## Социальный эффект и продолжение

Не заявлять «помогли N семьям» или «сократили время на X%»: пока нет измерений.
Предлагаемые пилотные метрики: доля пользователей, прошедших поиск→сравнение→понятный контакт;
время/ошибки до выбора; доля карточек с актуальными проверенными условиями; оценка полезности
раздела для мамы; доля пользователей, вернувшихся к своему плану. Contact click не состоявшееся посещение.
В реальной аналитике не хранить диагнозы/медтекст/данные детей; оценка пользы — добровольный feedback.

Устойчивость: назначить владельца каталога/модерации, процесс обновления и контакта с партнёрами,
согласовать эксплуатационные расходы/доступы/хранение. Сроки полного ТЗ не обещаны.
S1–S11 сохраняют весь full scope, но показ хакатона начинается с H1, а не с обещания готовой платформы.

## Мини-проверка с родителем (не заполнена вместо него)

Дать телефон, не объяснять кнопки. Не просить диагноз/документы/идентифицирующую историю.

- [ ] Найти, где помощь ребёнку, а где поддержка самой маме.
- [ ] Подобрать варианты по известному возрасту/языку, понять пустую выдачу и сброс.
- [ ] Сравнить2варианта и рассказать, что известно/что нужно уточнить.
- [ ] Дойти до обращения и правильно понять, что сообщение не отправлено.
- [ ] Найти идею для себя на15минут, в том числе в контексте беременности, сохранить в план.
- [ ] Сменить язык, найти сохранённый пункт и отметить его выполненным.
- [ ] Объяснить, какая кнопка/формулировка мешала и чего не хватило для доверия.

Заполнить после теста: дата/согласованный анонимный код участника, задачи без подсказок,
ошибки/непонятные слова, полезность активности для мамы,3приоритетных исправления.
Не публиковать имя/историю/запись родителя без отдельного разрешения. Результатов теста пока нет.
