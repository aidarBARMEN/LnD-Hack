# Mama Pro — решения и вопросы

## U1 — единый основной путь и учебный ПМПК

По прямому разрешению пользователя реализуется A1/U1. Основной поиск использует offerings
с уже структурированными возрастом/городом/языком и RU/KK. Расширенные R1-разделы сохранены
отдельно: их поля ещё недостаточны для подтверждённого персонального совпадения.
ПМПК представлен цитатой и явно подготовленным результатом; подтверждение родителем
меняет поисковые потребности, не создаёт медицинского назначения. Реальные uploads/NLP,
provider/retention/consent/access остаются отдельным этапом. Новых зависимостей нет.

Дата: 13.11.2026. `Предложено` не равно `Утверждено`.
Исторически S0 ограничивался документацией. Последующие команды разрешили H1, B1 и F1; full backend S1–S11 ещё не выполнен.
Предпочтительный стек указан пользователем; его конкретная интеграция и смена старой архитектуры
предлагаются ниже. Не отмечать вопросы отвеченными по умолчанию или из-за прошедшего времени.

## Журнал ADR

ADR-22 (T1, запрос пользователя): собственный Typeform-подобный ввод ребёнка вместо внешнего
сервиса. Сохраняются ChildProfile/CareDetails и прежние фильтры/подбор; только UI и валидация шага.
Нет передачи сведений третьим лицам и новой библиотеки. Базовая ветка7экранов, расширенная12,
включая обзор ответов. Пропуск допустим; возраст0–21 целый. Только финальное сохранение меняет
контекст; назад и точечное редактирование не теряют ответы. Нижняя навигация скрывается CSS
только при фактическом присутствии анкеты, чтобы не затрагивать поддержку мамы без профиля.


ADR-21 (R1, прямой запрос пользователя по DOCX 14.11.2026): добавить новый поиск/маршрут/
профиль/чаты/размещение поверх существующих модулей, без замены backend. Старый каталог и
сохранённые IDs доступны. Новые экраны сначала на русском; прежние переводы ru/kk сохраняются.
Беременность удалена из runtime-этапов и текстов по более позднему требованию.
Медицинские поля необязательны, только учебные; список помощи следует отметкам, не диагнозу.
`pdf-lib` + `@pdf-lib/fontkit` добавлены для локального скачивания PDF с кириллицей без передачи
сведений на сервер и зависимости от настроек печати. Noto Sans включён локально с SIL OFL1.1.
Документ квалификации в демо хранит только имя выбранного файла: содержание не читается и
не загружается. Имитация оплаты публикует карточку только в памяти вкладки, не даёт рейтинг.
Геолокация имитируется фиксированными расстояниями; реальные разрешения не запрашиваются.


ADR-20 (F1, запрос пользователя): анкета до подбора; няни с hourly/monthly/permanent и
бронированием; форум родителей; яркая палитра. В текущем окружении без Supabase/Auth
реализованы явно обозначенные локальные демо-бронь и форум. У них нет серверных API, оплаты,
доставки/подтверждения няне или модератору. Реальная многопользовательская реализация требует
S1/S2 и RLS, атомарной проверки слотов на сервере, верифицированного контента и модерации.
Анкета не требует диагноза/документов. Подбор по условиям, без клинической интерпретации.
Отмена освобождает период; удаление профиля очищает связанные демо-брони.
Периоды сравниваются с исключённой правой границей, постоянная занятость — без конечной даты;
дата/время демо — UTC+05:00, месяц прибавляется с ограничением последним днём месяца.


ADR-19 (подтверждено пользователем): публичное название «Бірге — вместе», в UI — «Бірге».
Этап B1 меняет только бренд/визуальную систему: оригинальные SVG, локальные системные шрифты,
единый brand.css поверх существующей базы. Новые библиотеки, доменная логика и backend не добавляются.
Mama Pro остаётся названием хакатона/организатора в исторических документах, не названием UI.

### Обновление после положения хакатона

ADR-18 (разрешён текущим запросом, full-scope решения не отменены): выполнить сначала H1 —
простой рабочий сценарий по §2.2/6.1 положения, ru/kk и поддержка мамы, включая беременность
как этап для немедицинского досуга. Подтверждение потребности — сообщение пользователя со слов родителя команды.
Новые backend/UI-библиотеки на H1 не добавляются; Supabase/Auth/RLS не имитируются без конфигурации.
План S1–S11 остаётся полным backlog; H1 не равен production-ready M01–M18.
Историческое правило «только S0 без кода» ниже описывает предыдущую сессию, текущую заменяет H1.
Официальные переводы юридического/медицинского контента по-прежнему требуют редактора;
новые ru/kk тексты H1 — учебный интерфейс/вымышленные данные, не официальные документы.

## Точные правила, требующие фиксации при реализации

1. Search: AND между полями, ANY внутри multi-value одного поля; цена/возраст/услуга проверяются
   на одной услуге. Unknown не становится бесплатным/подтверждённым. Возрастной поиск сохранён
   как полезная работающая функция прототипа; диапазон ребёнка Q04.
2. List/map: один DTO и загруженные страницы, точки только с координатами; количество unmapped
   видно. Нет point → district/name/id; координаты добровольно POST body, не GET URL/log.
3. Availability: предложенный TTL7дней, server updated_at; дата цены/карточки TTL окна не продлевает;
   expired при now≥expiry или end≤now; capacity0 не «есть места».
4. Duration: (0,15], (15,30], (30,60], (60,∞); 15/30/60 не попадают в два фильтра.
5. Чек-лист: общие шаги + whitelist административных условий; несколько правил одного шага OR,
   all/any внутри rule явно. Изменение анкеты сохраняет прежний done; current progress считает
   только доступные шаги. Никаких назначений оборудования/лечения автоматически по диагнозу.
6. Сессия/роли: проверка живого profile.status в БД и RLS, не только cookie/JWT; moderator/admin
   не назначаются при signup. Нет «смены роли» из parent UI для демонстрации.
7. Согласия: separate sensitive purpose; revoke прекращает обработку, не скрывает checkbox без эффекта.
   Export/delete/re-grant остаются возможны. Сроки очистки и доказательств ещё не согласованы.
8. File validation: extension+заявленный MIME недостаточны, server finalize сверяет size/magic/owner;
   документы private после approved, viewer не исполняет код. AV не обещан как реализованный.
9. Staff CRUD: moderator проверяет заявки/контент, admin управляет пользователями/ролями/settings.
   Каталожные справочники предложено admin-only, редакционные материалы moderator/admin.

## Первичные технические источники

Проверены 13.11.2026; перед использованием меняющихся API перепроверить применимую страницу.

- [Supabase SSR](https://supabase.com/docs/guides/auth/server-side/creating-a-client) — валидируемая auth session, защита от кеширования ответов с cookie.
- [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security) — политики данных; privileged secret/service-role может обходить RLS.
- [Storage access](https://supabase.com/docs/guides/storage/security/access-control) и [uploads](https://supabase.com/docs/guides/storage/uploads/standard-uploads) — закрытые файлы и прямой upload.
- [Vercel limits](https://vercel.com/docs/functions/limitations) — тело request/response функции4,5MB; основание ADR-06.
- [Supabase regions](https://supabase.com/docs/guides/platform/regions) и [Vercel regions](https://vercel.com/docs/functions/configuring-functions/region) — регион задаётся отдельно у каждого сервиса, это не автоматическое юридическое соответствие.
- [Supabase backups](https://supabase.com/docs/guides/platform/backups) — DB backup не включает объекты Storage.
- [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/) — атрибуция и правила публичных тайлов.

Правовой анализ страны запуска в S0 не проводился; эти ссылки не являются юридическим основанием
для обработки медицинских сведений детей. Не утверждать соответствие законодательству без отдельной проверки.
